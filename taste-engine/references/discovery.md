# Discovery protocol

## First: route, then discover depth

For new visual UI tasks with no confirmed style, first ask one concise **style-selection question** per `SKILL.md`. Wait. Do not generate UI code while the choice is outstanding.

Once a style is selected, capture only the preferences needed to customize it. Do not ask broad questionnaires. If user already gave a full style direction, proceed immediately. For existing UI bug fixes, preserve the established style without new discovery.

## Evidence hierarchy

1. Explicit feature likes/dislikes in the current request.
2. Explicit named style or approved project style config.
3. References with user-stated reasons for liking them.
4. Repeated patterns in multiple references.
5. Product purpose, brand, audience and platform conventions.
6. Isolated visual signals (provisional only).

Do not infer demographics, personality or private attributes from aesthetic preference. A screenshot does not endorse every visible feature.

## Discover after selection

- **Confirmed:** selected style, known brand constraints, explicit style exceptions.
- **Supported:** consistent evidence from references, not yet confirmed.
- **Open:** meaningful unresolved decisions such as whether to retain the current brand palette.
- **Provisional:** reversible details like an available fallback font.

Distinguish style from industry. “I need a trading dashboard” does not automatically mean “enterprise” or “dark cyberpunk”. If needed, ask which aesthetic they want.

## References

Analyze composition, typography, density, surface treatment, component states and responsive layout. Inspect actual screenshots when available rather than pretending to have viewed them. Ask which features in references are important only when disagreement materially affects the outcome.

## Selection copy examples

- In Indonesian: “Before I start, which visual style would you like: Claymorphism, Glassmorphism, Brutalism, Neo-brutalism, Minimalism, Swiss/Editorial, or another/custom style?”
- In English: “Before I build the interface, which visual style would you like: Claymorphism, Glassmorphism, Brutalism, Neo-brutalism, Minimalism, Swiss/Editorial, or another/custom direction?”

The agent's question should be a **single conversational question**, not a multi-field form.
