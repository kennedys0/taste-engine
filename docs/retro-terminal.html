Frequently Asked Questions

> Are CRT scanlines allowed under anti-slop rules?
Yes! Retro Terminal has an explicit exception in Taste Engine's anti-slop guidelines: subtle scanline rasters and phosphor glow are essential material-enabling properties that give terminal consoles authentic display depth. Removing them to satisfy a generic flat heuristic is classified as an aesthetic regression.
> How does Retro Terminal handle light mode without color collisions?
In light mode, Retro Terminal translates the aesthetic into a vintage teletype / parchment terminal: canvas becomes warm paper ivory (#F4F1EA), phosphor glow and dark scanlines are turned off, and bright amber inverts to deep carbon burnt amber (#5C3A00), maintaining WCAG AAA contrast (> 8.9:1).
> Is card-in-card permissible in Retro Terminal?
Yes! A nested surface is fully permitted when it models terminal multiplexers (tmux/screen panes), process monitoring wells, or code execution containers (e.g. --taste-term-well-bg with dashed border). Mindless decorative card stacking without distinct command boundaries remains disallowed.
> Can I install only Retro Terminal without other styles?
Yes, run npx skills add kennedys0/taste-engine --skill taste-style-retro-terminal to install this standalone skill directly into your AI coding agents.
> How does Retro Terminal maintain responsiveness down to 320px?
All typography scales down using fluid CSS clamp() formulas, all command pills feature scrollable single-line wrappers, top navigation collapses into an accessible mobile hamburger drawer, and circular elements enforce aspect-ratio: 1 / 1 !important; flex-shrink: 0 !important; to eliminate oval squishing.
