Architecture & Pipeline

How Taste Engine Works

From a raw user prompt to a world-class production interface — here is the 4-phase transformation pipeline executed by your AI agent.

Phase 01
🎯

Archetype Discovery

The agent analyzes project domain, target audience, and brand personality. Requirements are intelligently mapped to the optimal aesthetic (e.g., Fintech & Analytics → Data Cockpit, Developer Tools → Retro Terminal or Swiss Editorial).

  • Automatic domain-context mapping
  • User tone & persona calibration
  • Prevents generic default blue templates
Phase 02
📐

Mathematical Design Tokens

Instead of arbitrary CSS, Taste Engine injects a unified token architecture with exact typographic ratios, 4px/8px spatial rhythm, specific border radii, and consistent semantic color roles.

  • Strict font family & scale pairings
  • Layered elevation shadows (multi-stop)
  • Modular CSS custom properties
Phase 03
🌗

Paired Dark/Light Coupling

Background, surface, ink (text), and border tokens invert in mathematically synchronized pairs. Completely eliminates fatal contrast collisions like black text on dark backgrounds or white text on pale surfaces.

  • Guaranteed WCAG AA contrast ratio (≥ 4.5:1)
  • Automatic theme inversion via [data-theme]
  • Zero manual color patching required
Phase 04
🛡️

Anti-Slop Quality Gate

Before delivering code, the agent validates the UI against the 7 Universal Quality Gates: no floating ungrounded cards, no generic AI glow halos, no meaningless glassmorphism, and full button state completeness.

  • Eliminates cheap AI design clichés
  • Enforces hover, active & focus states
  • Production-ready for React, Next.js, Vue, Tailwind, etc.
Installation Guide

Install Taste Engine in Seconds

Choose your preferred AI Agent below and run the one-line installation command.

Antigravity IDE — Global or Local Setup 
# Global installation across all your Antigravity workspaces:
node bin/taste-engine.mjs install --agent antigravity --global

# OR install locally to the active project workspace:
node bin/taste-engine.mjs install --agent antigravity
💡 Antigravity Tip: Once installed, the skill automatically activates in ~/.gemini/config/skills/taste-engine. You can immediately ask in chat: "Apply Neo-Brutalism in Dark Mode for this dashboard."
Antigravity CLI (agy) Terminal 
# Add via Universal Skills CLI:
npx skills add kennedys0/taste-engine

# Verify skill installation status in agy:
agy skills list
💡 CLI Info: Antigravity CLI automatically loads all skills registered in your user configuration directory.
Anthropic Claude Code 
# Installation via Taste Engine Installer:
node bin/taste-engine.mjs install --agent claude --global

# OR via Skills CLI:
npx skills add kennedys0/taste-engine
💡 Claude Code Integration: Skill installed to ~/.claude/skills/taste-engine and immediately available to the Claude Code CLI.
OpenAI Codex & GitHub Copilot Workspace 
# Installation for Codex / Copilot context:
node bin/taste-engine.mjs install --agent codex --global

# Or install directly to your project repository:
node bin/taste-engine.mjs install --agent codex
💡 Codex / Copilot: Skill guidance files reside at ~/.codex/skills/taste-engine or .agents/skills/taste-engine in your repository.
Universal Skills CLI (npx skills) 
# Install the entire Taste Engine pack in one command:
npx skills add kennedys0/taste-engine

# List installed skills on your machine:

💡 Ecosystem Standard: Works with all agent environments supporting the official Agent Skills Registry standard.

By default, AI coding agents produce uniform, repetitive frontend designs (AI-slop): floating purple shadows, low contrast, ungrounded cards, and generic layouts that look cheap and unfinished.

Every style in Taste Engine enforces Strict Paired Coupling. Color tokens are mathematically paired across background, surface, ink (text), and borders.

When toggling between [data-theme="dark"] and [data-theme="light"], all token pairs invert symmetrically and are guaranteed to meet minimum WCAG AA (≥ 4.5:1) readability standards. Anti-slop rules explicitly ban dark text on dark surfaces or pale text on light cards.

Token Reference

Standard Token Architecture

Every style follows a standardized CSS variable naming convention, easily mapped to Tailwind CSS theme configuration or plain CSS custom properties.

CSS Variable Pattern Semantic Role Dark Mode Behavior Light Mode Behavior
--taste-[style]-bg Canvas background layer Deep matte charcoal / velvety graphite Crisp white / soft pale slate tint
--taste-[style]-surface Card, panel, and modal containers Elevated matte surface with subtle bevel Clean elevated card with soft rim
--taste-[style]-text Primary readable typography High-contrast crisp white (min 4.5:1) High-contrast slate/black (min 4.5:1)
--taste-[style]-muted Secondary labels & subtitles Medium cool grey (accessible contrast) Medium slate grey (accessible contrast)
--taste-[style]-border Card outlines & structural lines Subtle translucent white rim Subtle translucent dark rim
--taste-[style]-accent Primary action buttons & indicators Vibrant neon purple / cyan gradient Deep, contrast-anchored purple highlight
Quick Starter CSS Boilerplate 
/* Root Dark Theme Default */
:root {
  --app-bg: var(--taste-bento-bg, #15171c);
  --app-surface: var(--taste-bento-surface, #1e2026);
  --app-text: var(--taste-bento-text, #f8fafc);
  --app-border: var(--taste-bento-border, rgba(255, 255, 255, 0.08));
  --app-accent: var(--taste-bento-accent, #a855f7);
}

/* Light Theme Transition */
[data-theme="light"] {
  --app-bg: #f1f4f8;
  --app-surface: #ffffff;
  --app-text: #0f172a;
  --app-border: rgba(0, 0, 0, 0.08);
  --app-accent: #7c3aed;
}
