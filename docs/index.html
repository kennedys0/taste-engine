Architecture Flow

How Taste Engine Works

From a user prompt to a production-grade interface — here is the 4-phase transformation pipeline executed by your AI agent.

Phase 01

Archetype Discovery

The agent inspects project context, domain, and user persona. It maps requirements to the optimal visual archetype (e.g. Fintech → Data Cockpit, Dev Tools → Retro Terminal or Swiss Editorial) before writing UI code.

  • Context-to-aesthetic mapping
  • Persona & tone calibration
  • Eliminates generic blue templates
Phase 02

Mathematical Tokens

Injects structured design tokens: calibrated typographic ratios, strict 4px/8px spatial rhythm, specific border radii, and predictable CSS variables instead of arbitrary inline styles.

  • Strict font & scale pairings
  • Consistent shadow elevations
  • Standardized CSS variables
Phase 03

Paired Dark/Light Coupling

Background, surface, ink (text), and border tokens invert in mathematically synchronized pairs. Completely prevents contrast collisions such as black text on dark surfaces or white on white.

  • Guaranteed WCAG AA (min 4.5:1)
  • Automatic [data-theme] inversion
  • Zero manual color patching
Phase 04

Anti-Slop Quality Gate

Before delivering code, the agent validates the UI against the 7 Universal Quality Gates: no floating ungrounded cards, no generic AI glow halos, no meaningless glassmorphism, and full state completeness.

  • Bans repetitive AI cliches
  • Enforces hover & active states
  • Production-ready clean CSS
Installation

Install in Seconds

Select your target AI Agent environment below to get the single-line installation command.

Antigravity IDE — Global or Project Setup 
# Global install across all Antigravity workspaces:
node bin/taste-engine.mjs install --agent antigravity --global

# OR local install into the current project workspace:
node bin/taste-engine.mjs install --agent antigravity
Antigravity IDE: Installed to ~/.gemini/config/skills/taste-engine. The IDE discovers the skill automatically. Prompt in chat: "Apply Neo-Brutalism in Dark Mode for this dashboard."
Antigravity CLI (agy)

npx skills add kennedys0/taste-engine

FAQ

Frequently Asked Questions

Technical answers on framework independence, contrast gating, codebase preservation, and custom styling.

By default, AI coding agents generate uniform, repetitive frontend designs (often termed AI-slop): ungrounded floating cards, low-contrast text, purposeless blur effects, and generic blue-purple gradients.

Taste Engine is an intelligence skill pack that equips AI agents with 10 distinctive aesthetic archetypes (Bento, Brutalism, Claymorphism, Cockpit, Cyberpunk, Glassmorphism, Minimalism, Retro Terminal, Skeuomorphism, Swiss Editorial) backed by strict quality gates to produce production-grade frontend code.

No. Taste Engine is 100% framework-agnostic. It injects pure design principles, mathematical tokens, and native CSS recipes.

You can use it seamlessly with React, Next.js, Vue, Svelte, Nuxt, Astro, HTML/CSS, Tailwind CSS, shadcn/ui, MUI, or any other UI stack.

Every style in Taste Engine enforces Strict Paired Coupling. Tokens for background, surface, ink (text), and borders are defined as synchronized mathematical pairs.

When toggling between [data-theme="dark"] and [data-theme="light"], all token pairs invert symmetrically and are guaranteed to meet minimum WCAG AA (≥ 4.5:1) readability standards. Anti-slop quality gates explicitly ban dark text on dark surfaces or pale text on light cards.

No. Taste Engine is non-destructive and additive. All tokens and CSS classes use unique namespaces such as --taste-[style]-*, ensuring zero collision with your global stylesheets.

Quality gates also instruct the agent to respect existing component architecture and naming conventions in established projects.

Yes. Taste Engine provides 10 independent standalone skills in the optional-standalone-skills/ directory. You can install each style individually using:

npx skills add kennedys0/taste-style-[style-name]

For example: npx skills add kennedys0/taste-style-cyberpunk-hud. This minimizes token usage if your project only requires a single aesthetic.

In Antigravity IDE, check your installed skills list or run agy skills list in the CLI.

To test directly in chat, ask: "Use Taste Engine to review and redesign this card component with a Bento Grid aesthetic." Your agent will recognize the skill and apply its architectural constraints.

Yes. You can override CSS custom properties in your stylesheets (for example, overriding --taste-cyber-accent: #00ffcc;).

To contribute a new aesthetic pack, add a markdown specification in taste-engine/styles/ and validate it with our test runner: python taste-engine/scripts/validate-pack.py.
