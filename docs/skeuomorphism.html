Design Rationale

Frequently Asked Questions

Clarifications on physical affordance, anti-slop boundaries, and light mode coupling.

Why does Taste Engine distinguish genuine Skeuomorphism from flat cards?
A flat card with standard rounded corners and a single subtle gradient is an aesthetic failure in Skeuomorphism. Genuine skeuomorphic UI demands directional light physics: top 1px specular highlights, bottom drop shadows, recessed well cavities with deep inset shadows, and 1.5px mechanical travel on button depression.
Are card-inside-card nested surfaces allowed in Skeuomorphism?
Yes, when representing physical hardware sub-chassis, modular rack-mount bays, or recessed display wells sunken into the main chassis faceplate (using `--taste-skeuo-well-bg` and `--taste-skeuo-well-inset`). Mindless decorative nesting without mechanical or enclosure logic remains disallowed.
How does the Light Mode anti-collision rule protect readability?
In light mode, the chassis transitions to brushed aluminum (`#E9ECEF`). All engraved labels, dial numbers, and control text strictly flip to deep charcoal (`#1F2937`), delivering a 10.8:1 contrast ratio that completely prevents white-on-silver legibility failures.
Can I install just the Skeuomorphism skill in my agent?
Yes! Run `npx skills add kennedys0/taste-engine --skill taste-style-skeuomorphism` to install only this standalone package without pulling other styles.
