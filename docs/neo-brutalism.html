FAQ & Verification

Frequently Asked Questions

Why is this Proof of Work built in Neo-Brutalism?
Taste Engine operates on the principle that aesthetic fidelity must be recognizable from the rendered interface. By building this entire installation guide in Neo-Brutalism, you can directly verify the physics, contrast pairing, and lack of AI-slop before adopting the skill into your agents.
Why are hard offset shadows permitted by the anti-slop rules?
Taste Engine’s anti-slop rules contain an explicit material exception for Neo-Brutalism: 0-blur directional offset drop shadows and solid black outlines are material-enabling properties essential to neo-brutalist tactile physics. Removing them to satisfy a generic minimal heuristic is classified as an aesthetic regression.
How does Dark Mode prevent black-on-black shadow collision?
In dark mode, Neo-Brutalism flips both borders and 0-blur offset shadows from black to stark white (#FAFAFA) or vivid yellow. This ensures zero black-on-black collision and preserves tactile depth on dark surfaces.
Is Card-in-Card permissible in Neo-Brutalism?
Yes! A nested surface is fully permitted when it encapsulates a distinct semantic boundary, elevated parameter well, or code container (e.g. --taste-neo-card-elevated with 2px solid border and 4px offset shadow). Mindless decorative card stacking without semantic distinction remains disallowed.
How does Neo-Brutalism maintain mobile responsiveness down to 320px?
All typography scales down using fluid CSS clamp() formulas, all command pills feature scrollable single-line wrappers, top navigation collapses into an accessible mobile hamburger drawer, and circular elements enforce aspect-ratio: 1 / 1 !important; flex-shrink: 0 !important; to eliminate oval squishing.
